Overview

The demo in this repository implements a minimal provider and consumer following the Service-Oriented Device Connectivity (SDC) family of standards under IEEE 11073. This document explains the model in enough depth to read the source code without prior SDC background.

IEEE 11073 — family map

Part Purpose
11073-10207 Domain Information & Service Model (BICEPS)
11073-20701 Service-Oriented Device Connectivity
11073-20702 Medical Devices Profile for Web Services
11073-10101(nu) Nomenclature codes

BICEPS

BICEPS = Basic Integrated Clinical Environment Protocol Specification.

Every provider hosts an MDIB (Medical Device Information Base) which is split into:

  • Descriptors — the static structure: what does this device even have?
  • States — the current value of everything the descriptors describe.

The hierarchy is roughly: 

MDS (Medical Device System)
└── VMD (Virtual Medical Device)
    └── Channel
        └── Metric  ← the actual measurement point

RealTimeSampleArrayMetricState is the state variant for waveforms: one report carries a batch of consecutive samples together with the declared sample_rate_hz, so the transport rate can be throttled (e.g. 10 Hz reports) while the underlying sample rate is preserved (e.g. 100 Hz per-sample data) — Nyquist-safe by construction.

Sequence

A minimal interaction looks like this: 

Consumer                       Provider (wearable)
   |                                 |
   |--- Probe (WS-Discovery) ------->|
   |<-- ProbeMatch ------------------|
   |                                 |
   |--- GetMdib -------------------->|
   |<-- MDIB (descriptors + states)--|
   |                                 |
   |--- Subscribe (State Events) --->|
   |<-- SubscribeResponse -----------|
   |                                 |
   |<== EpisodicMetricReport ========|
   |<== EpisodicMetricReport ========|
   |<== EpisodicAlertReport =========|

Safety Contexts

A Set operation in SDC is never just a remote procedure call. It carries a Safety Context proving the operation is:

  • targeting the correct patient (PatientContext),
  • in the correct location (LocationContext),
  • during a valid workflow (WorkflowContext),
  • and by a party currently permitted to issue it (ParticipantKey).

This is the single most important concept that separates SDC from a naïve service bus over TLS.

Transport — Medical DPWS

  • WS-Discovery over UDP multicast (device discovery)
  • SOAP over HTTP(S)/TCP (messages)
  • WS-Eventing (subscriptions)
  • TLS (transport security)
  • WS-Security + XML Signature (message-level integrity above TLS)

Components

The demo splits into the components below. Each component declares which requirements from specs.org it implements (:implements: property), in the spirit of sphinx-needs: the specification carries the what, the architecture carries the how, and the REQ-xxx IDs bind them.

COMP-MDIB — Information Model

The static BICEPS descriptor tree (MDS → VMD → Channel → Metric) plus the mutable state snapshot. The waveform metric declares its own sample_rate_hz, which the transport layer relies on to reconstruct per-sample timestamps at the consumer.

COMP-GAIT — Gait Analysis

Windowed FFT with parabolic peak interpolation over the plausible gait band (0.5–3.5 Hz). Includes an energy gate that forces 0.0 (rather than NaN) when the signal is at noise level, so "standing" is a first-class state on the wire.

COMP-STREAM — Sample Pump & Report Batcher

Reads CSV samples at the nominal rate and buffers every sample into a RealTimeSampleArrayReport, flushed on a fixed report interval (100 ms). Report rate and sample rate are decoupled; Nyquist is preserved by construction.

COMP-EVENTS — Episodic Report Delivery

Long-poll HTTP facade with monotonically increasing seq numbers, mirroring WS-Eventing semantics. /mdib and /state are served independently so descriptors and states can be fetched separately.

COMP-SUB — Consumer Subscription Client

Performs GetMdib, then loops on /events?after=seq. On any error it flips the connection status and retries every 2 s. Reconstructs per-sample timestamps from t_start + i / sample_rate_hz for waveform reports.

COMP-VIEW — Rolling In-Memory Views

Time-bounded deques that evict against wall-clock time (not just on insert), so a paused stream empties visibly on the dashboard.

COMP-DASH — Dashboard UI + JSON API

Serves index.html plus /api/status, /api/cadence, /api/accel for the browser to poll. Renders cadence, vertical-axis waveform and connection state.
