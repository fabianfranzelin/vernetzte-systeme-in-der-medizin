The Demo — BICEPS in SDC

BICEPS (IEEE 11073-10207): the information model behind SDC.

  • Domain model, not a wire format.
  • Hierarchy: MDS → VMD → Channel → Metric, joined by handle.
  • Descriptor vs. state: static structure vs. live values.
  • Typed metrics: NumericMetric, RealTimeSampleArrayMetric, alerts, contexts.
  • MDC nomenclature: semantic codes (MDC_ACT_STEP_RATE), not just numbers.

BICEPS in the demo — descriptor

demo/provider.py — Medical Device Information Base (MDIB) 

# ---------- BICEPS-style information model (static descriptors) ----------
MDIB = {
  # medical device system
  "mds": {
    "handle": "mds.wearable", "model": "gaitband-sim",
    # Virtual medical device
    "vmds": [{"handle": "vmd.gait", "channels": [{"handle": "channel.imu",
      "metrics": [
        {"handle": "metric.cadence",
         "kind": "NumericMetric",
         "unit": "1/min", "code": "MDC_ACT_STEP_RATE"},
        {"handle": "metric.accel",
         "kind": "RealTimeSampleArrayMetric",
         "unit": "g", "code": "MDC_ACT_ACCEL_VEC",
         "sample_rate_hz": 100.0, "components": ["ax","ay","az"]},
      ]}]}]}}

BICEPS in the demo — state split

demo/provider.py — States 

STATE = {
    "metric.cadence": {"value": None, "unit": "1/min",  "ts": 0.0},
    "metric.accel":   {"value": [None]*3, "unit": "g",  "ts": 0.0},
}
  • Same handles as the MDIB
  • Mutable — updated each sample
  • Self-contained values — unit + timestamp travel with the value.
  • Snapshot on demand via GET /state; deltas pushed on GET /events.

Conclusion — Clinics to Cars

  • Same pattern across domains: discover → describe → subscribe → stream.
  • Medical: SDC (IEEE 11073) — this demo.
  • Automotive: SOME/IP — service discovery + pub/sub on IP.
  • Industrial / avionics: DDS — data-centric pub/sub.
  • Takeaway: service-oriented device connectivity is a pattern, not a stack.
